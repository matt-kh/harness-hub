## Kubernetes
- **Read-only by default.** Use the `k8s` CLI (skill `k8s`) first; raw kubectl only as
  `kubectl --context C --request-timeout=20s … -o json | jq`, and `helm --kube-context C`.
- **Discover contexts with `k8s contexts`, never hardcode them.** Pass `--context` explicitly on
  every command; `kubectl config use-context` and every other kubeconfig edit is **denied** — the
  kubeconfig is shared with the user's shell. Reading `~/.kube/*`, `$KUBECONFIG` or
  `kubectl config view --raw` is denied too.
- Banner on stderr is `context=<ctx> server=<ver> [ns=<ns>] [PROD]`. Prod contexts/namespaces
  (matching `K8S_PROD_RE`, default: `prod`/`production` as a whole segment) read freely — but
  there **remediations are suggestions for the human**, stated with their blast radius, never
  executed.
- **Prompts (ask):** kubectl mutations (apply/delete/edit/patch/scale/label/rollout restart/…),
  exec-class (`exec|attach|cp|debug|port-forward|proxy`), `kubectl create token`, `helm
  install|upgrade|uninstall|rollback|test|push`, `helm get values|all|manifest`, argocd/flux/eksctl
  mutations, `pulumi up|destroy|refresh`, `terraform apply|destroy`. `--dry-run=client|server` is
  exempt (`--dry-run=none` is not). Agents never run these — they hand the command to the user.
- **Secrets: keys and byte sizes only.** `k8s secret-keys NS NAME`, or pipe through `| k8s redact`
  (which also lifts the `helm get values` prompt). `get secret … -o yaml|json|jsonpath|go-template`
  and `get --raw …/secrets` are **denied**; never `base64 -d` Secret data.
- Agents: `k8s-triage` (incident → root cause + remediation), `k8s-auditor` (posture review);
  `infra-architect` is design-only. Fixes go into the chart / GitOps repos (GitOps checkout: `k8s.gitops_root`) via their repo-level skills, never the live cluster.

A repository's own instructions for the same action replace this block.
